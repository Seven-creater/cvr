---

## 1. 任务定义

**Composed Video Retrieval (CVR)**：给定参考视频 + 编辑指令，从 943 个候选视频中检索出目标视频。

- **输入**：reference video（视觉+音频）+ edit text（文本）联合输入
- **输出**：按相关性排序的视频列表
- **评估**：R@1 / R@5 / R@10（target 视频是否出现在 top-K 中）

---

## 2. 输入输出

### 输入

- **reference_video**：参考视频（6s segment，含音频）
- **edit_text**：编辑指令（如 "turn the trading card to show the back"）

Query 构造方式：
```
payload = {
    "video": reference_video_path,
    "text": "Edit the reference video so that: {edit_text}"
}
```
将 video + text 组合传入 e5 的 `encode_document()`，得到融合后的 multimodal embedding。

### 具体例子

```
参考视频: 球星卡正面（David Robinson & Hakeem Olajuwon）
编辑指令: "turn the trading card to show the back"
目标视频: 球星卡背面

Query: {
    video: reference.mp4,
    text: "Edit the reference video so that: turn the trading card to show the back"
}

E5 编码 → 3584 维 embedding
在 943 个 target video embedding 中检索
结果: target_rank = 4（top-5 命中）
```

---

## 3. 数据集

Single-source video pair 数据集，943 条样本。

### 构建流程

1. 从 193 个源视频（94 daily_omni + 99 worldsense）中，每个切成 5 个 6s segment
2. 同源 segment 两两配对，生成 C(5,2)=10 个候选 pair
3. Omni（qwen3-omni）对每个 pair 做差异标注 + 质量评分
4. 筛选 `final_omni_accept=True` 的 pair，得到 943 条

### 差异类型分布

| 类型 | 数量 | 占比 |
|------|------|------|
| scene | 513 | 54.4% |
| object_presence | 276 | 29.3% |
| action | 101 | 10.7% |
| attribute | 45 | 4.8% |
| object_count | 7 | 0.7% |
| audio_event | 1 | 0.1% |

### 三元组格式

```
triplets_media/{sample_id}/
├── reference.mp4    # 参考视频（6s，含音频）
├── target.mp4       # 目标视频（6s，含音频）
└── edit_text.txt    # 编辑指令
```

## 4. 方法

### E5-Omni-7B

[e5-omni-7B](https://huggingface.co/Haon-Chen/e5-omni-7B) 是一个多模态 embedding 模型，基于 Qwen2.5-Omni 架构，内置 Whisper 音频编码器（32层，128 mel bins），支持 video + text + audio 联合输入，输出 3584 维统一 embedding。通过 `sentence-transformers` 加载。

### 音频处理

`load_audio_from_video=True`，transformers 的 `apply_chat_template` 通过 librosa 从视频文件提取音频（16kHz），作为独立 audio 输入传入 Qwen2.5-Omni processor。

### 三种实验配置

| 配置 | query 输入 | ref 音频 | target 音频 | edit_text |
|------|-----------|---------|------------|-----------|
| **composed** | video + text | 原始 | 原始 | 是 |
| **video-only** | video only | 原始 | 原始 | 否 |
| **composed ref-silent** | video + text | 静音 | 原始 | 是 |

### 检索流程

**Phase 1: 离线索引**
```
943 个 target 视频（含音频）
    │
    ▼
E5 encode_document(video, load_audio_from_video=True)
  ├─ librosa 提取音频（16kHz）
  ├─ torchvision 采样视觉帧（1fps）
  └─ Qwen2.5-Omni → 3584 维 embedding
    │
    ▼
target index (943 × 3584, L2 归一化)
```

**Phase 2: 在线查询**
```
输入：reference.mp4 + edit_text
    │
    ▼
apply_chat_template(load_audio_from_video=True)
  ├─ 从视频提取音频 + 采样视觉帧
  └─ 渲染 text + video + audio token
    │
    ▼
E5 encode_document → 3584 维 query embedding
    │
    ▼
余弦相似度检索 → 排序结果
```

### 模型配置

| 参数 | 值 |
|------|-----|
| 模型 | e5-omni-7B |
| 架构 | Qwen2.5-Omni |
| 音频编码器 | Whisper（32层，128 mel bins） |
| Embedding 维度 | 3584 |
| torch_dtype | bfloat16 |
| video_max_pixels | 50176 |
| video_fps | 1 |
| load_audio_from_video | true |
| batch_size | 1 |

## 5. 实验执行

三组实验在 GPU 4/5/6 上并行运行，共享同一份 audio-on target index。

**Exp1: Composed** — GPU 4（编码 target + query）：
```bash
setsid nohup bash scripts/run_e5_cvr_eval.sh \
  --triplets-jsonl ... --gpu-id 4 \
  --query-mode composed --reference-audio-mode original \
  --video-audio-mode on \
  > logs/e5_audio_on_composed_eval_*.log 2>&1 < /dev/null &
```

**Exp2: Video-only** — GPU 5（复用 target index）：
```bash
setsid nohup bash scripts/run_e5_cvr_eval.sh \
  --triplets-jsonl ... --gpu-id 5 \
  --query-mode video-only --reference-audio-mode original \
  --video-audio-mode on \
  --target-index-dir runs/e5_audio_on_composed_eval_*/target_index \
  > logs/e5_audio_on_video_only_eval_*.log 2>&1 < /dev/null &
```

**Exp3: Composed ref-silent** — GPU 6（复用 target index）：
```bash
setsid nohup bash scripts/run_e5_cvr_eval.sh \
  --triplets-jsonl ... --gpu-id 6 \
  --query-mode composed --reference-audio-mode silent \
  --video-audio-mode on \
  --target-index-dir runs/e5_audio_on_composed_eval_*/target_index \
  > logs/e5_audio_on_composed_ref_silent_eval_*.log 2>&1 < /dev/null &
```

## 7. 分析

### 7.1 E5 composed 大幅领先所有 AVIGATE 方法

| 对比 | R@1 | R@5 | R@10 |
|------|:---:|:---:|:----:|
| vs AVIGATE T2V baseline | **+6.3pp** | **+21.3pp** | **+20.0pp** |
| vs AVIGATE T2V + Agent | **+3.2pp** | **+19.8pp** | **+19.3pp** |
| vs AVIGATE V2T + Agent | **+2.7pp** | **+20.6pp** | **+20.3pp** |

### 7.2 edit_text 贡献显著

edit_text 在所有指标上带来稳定提升：R@1 +4.1pp, R@5 +8.9pp, R@10 +5.8pp。编辑指令帮助模型从同源视频中精确定位目标。

### 7.3 参考视频音频无正向贡献

ref-silent（静音 reference）的 R@1=0.2078 反而比原始（R@1=0.2025）略高 +0.5pp，R@10 也从 0.9841 升到 0.9915。去掉 reference 音频后检索结果不降反升。

可能原因：
1. **数据集特性**：99.9% 的编辑指令描述视觉变化，仅 0.1% 涉及音频事件，音频不是区分性信号
2. **音频噪声**：加入音频引入了额外维度，可能干扰视觉特征匹配

### 7.4 R@5/R@10 大幅领先

- R@5 从 AVIGATE 的 ~0.60 提升到 **0.81**（+21pp）
- R@10 从 ~0.78 提升到 **0.98**（+20pp）

E5 的 embedding 空间能有效区分同源不同 segment 的视频。

### 7.5 R@1 仍然偏低

绝对值 ~0.20（~190/943），原因：
1. **同源干扰** — 193 个源视频 × 5 个 segment，top-1 区分困难
2. **零样本推理** — E5 未在本任务上微调
3. **部分差异极小** — attribute、object_count 类型变化不明显

## 9. 下一步建议

- **标准 CVR benchmark 评测** — 在 CIRR、FashionIQ 等公开 benchmark 上跑 E5
- **按差异类型分桶评估** — 分析 scene / action / attribute 等类型的表现差异
- **微调** — 用 943 条数据做 few-shot 微调提升 R@1
- **构建音频编辑数据集** — 当前数据集仅 0.1% 涉及音频，需专门数据才能评估音频编码器价值
- **与 AVIGATE 融合** — E5 embedding + AVIGATE embedding ensemble
