# AudioDelta Loss Schedule 控制变量实验报告

日期：2026-05-28

## 1. 背景

AudioDelta 的目标是在已冻结的 E5 多模态 encoder 之上，训练一个轻量 adapter，使其能够区分"对音频做过编辑的视频"（target）和"原始未编辑视频"（reference）。

训练数据是一条 triplet：（query 描述, target 视频, reference 视频）。adapter 需要学会：当 gallery 里同时存在 target、reference 和各种干扰项时，把 target 排到最前面。

本实验通过控制变量法，逐步打开 loss 组件，验证每个组件的独立贡献和组合协同效应，并确定最优训练步数。

## 2. Loss 组件定义

| 简称 | 全称 | 参数 | 含义 |
|---|---|---|---|
| baseline | E5-Omni recipe | — | 标准主 loss。基于 triplet + margin，将 query 与 positive（target）拉近、与 negative 推远。这是 adapter 训练的最低要求，不加任何额外 loss。 |
| ref | Reference-negative loss | lambda_ref=0.3 | 额外施加一个 loss 项，显式要求 target 的分数高于 reference（同源未编辑视频）。标准 triplet loss 把 reference 当普通 negative 处理，区分力度不够，ref loss 弥补这个不足。 |
| delta | Audio-delta loss | lambda_delta=0.5 | 显式建模"音频编辑前后的差异"，要求 adapter 在嵌入空间中放大 target 与 reference 之间的音频编辑信号。这是 AudioDelta 的核心创新 loss。 |
| hn | Hard-negative margin loss | lambda_hn=0.5 | 对三类难负例（visual_hard / audio_hard / asr_hard）施加额外的 margin 约束，迫使 adapter 在困难样本上也保持区分度。 |

## 3. 配置命名规则

- **S 系列**（Single）：只开一项 loss，做单因素控制变量。S1 = 全部关闭（纯 baseline），S2/S3/S4 = 各开一项。
- **C 系列**（Combo）：组合多项 loss。C1 = ref + delta（实验确定的最优组合），C2 = ref + delta + hn（全组合）。
- **后缀**：`_steps120` 表示训练 120 步，`_low_lr` 表示使用更低学习率（1e-4 vs 默认 3e-4）。

## 4. 实验设计

### 4.4 评估协议

所有配置复用同一套 cache，在两组 gallery 上评估：

- **V_T**（视频+文本，无音频）：纯视觉-文本检索基线。gallery 中每个视频只有视觉帧和文本描述。
- **V_A_T**（视频+音频+文本，全模态）：AudioDelta 的核心评估场景。gallery 中每个视频额外包含音频信息。

评估 gallery 结构（共 1000 条）：

| 类型 | 数量 | 说明 |
|---|---:|---|
| positive | 128 | 正确的 target 视频 |
| reference_negative | 128 | 同源但未做音频编辑的参考视频 |
| visual_hard | 128 | 视觉上相似的难负例 |
| audio_hard | 128 | 音频上相似的难负例 |
| asr_hard | 128 | ASR 文本相似的难负例 |
| distractor | 262 | 随机干扰项 |
| local_same_source | 36 | 同源 local 候选（来自同一原始视频的不同片段） |
| local_fallback_visual | 62 | local 视觉回退候选 |

查询集：128 条。同源击败指标基于 36 条 local_same_source + 538 条 reference = 574 条 same_source_any。

### 4.5 关键指标

| 指标 | 含义 | 方向 |
|---|---|---|
| R@1 / R@5 / R@10 | target 排在 top-K 的 query 比例 | 越大越好 |
| Target Beats Ref | target 分数 > reference 分数的 query 比例 | 越大越好 |
| Gap | target 与 reference 分数差均值 | 越接近 0 越好（负值表示 reference 偏强） |
| RefNeg | target 击败 reference_negative 的比例 | 越大越好 |
| LocalSameSource | target 击败 36 条 local_same_source 的比例 | 越大越好 |
| SameSourceAny | target 击败全部 574 条同源负例的比例（ref + local） | 越大越好 |

### 6.3 单因素分析（V_A_T，以 S1 为参照）

| 对比 | R@1 变化 | Beats Ref 变化 | Gap 变化 | 解读 |
|---|---|---|---|---|
| S2（+ref）vs S1 | -0.0234 | +0.0078 | +0.0001 | 单独 ref 让 R@1 降了，但 target vs reference 区分力略有提升 |
| S3（+delta）vs S1 | **+0.0078** | **+0.0157** | +0.0000 | R@1 和区分力都提升，单项贡献最大 |
| S4（+hn）vs S1 | +0.0078 | +0.0078 | +0.0006 | Gap 改善最大（-0.0033 → -0.0027），拉近了 positive 与 target |

### 6.4 组合分析（V_A_T）

| 对比 | R@1 变化 | Beats Ref 变化 | 解读 |
|---|---|---|---|
| S2 → C1（加 delta） | +0.0234 | **+0.0391** | 在 ref 基础上加 delta，Beats Ref 大幅提升 |
| S3 → C1（加 ref） | -0.0078 | +0.0312 | 在 delta 基础上加 ref，Beats Ref 大幅提升 |
| C1 → C2（加 hn） | -0.0078 | -0.0078 | 加 hn 反而全部下降 |

**关键**：ref 单独贡献 +0.008，delta 单独贡献 +0.016，但 ref+delta 组合贡献 +0.047 > 两者之和（+0.024），存在明确的协同效应。hn loss 无增益。

### 6.5 V_T vs V_A_T 对比

V_T 下 S1 基线全面领先，加任何额外 loss 都降。V_A_T 下 C1 ref+delta 最优。这说明 **ref 和 delta loss 的增益完全依赖音频模态**：没有音频时，这些 loss 试图放大的"音频编辑差异"在纯视觉文本空间里找不到对应信号，反而干扰了 baseline 学到的通用检索模式。

## 9. Adapter 对比 Base E5

Base E5（无 adapter）V_A_T R@1 = 0.0156。加入 adapter 后 R@1 提升至 0.21~0.34，提升 **13~22 倍**。

## 11. 结论

### 11.1 核心发现

1. **C1_ref_delta 在 120 步是全局最优配置**。Beats Ref = 0.4453（最高），SameSourceAny = 0.8763（最高），R@1 = 0.3281（并列最高）。ref + delta 存在明确的协同效应（组合贡献 +0.047 > 单独之和 +0.024）。

2. **C1 存在明确的早停窗口**。120 步后所有指标单调下降，180/240/600/1200 步均不如 120 步。220 样本小数据集上 adapter 过拟合严重。

3. **S1 基线更耐长训**。120~600 步间波动小，无急速下降。没有早停机制时 S1 是更安全的选择。

4. **hn loss 无增益**。C1 → C2 加入 hn 后指标略降。220 样本规模下 hard-negative 信噪比不够。

5. **低学习率（1e-4）导致欠拟合**。不能缓解 C1 的过拟合问题。标准 lr（3e-4）+ 早停是正确策略。

6. **ref + delta 的增益完全依赖音频模态**。V_T（无音频）下 S1 基线全面领先，C1 反而最差。V_A_T（有音频）下 C1 最优。这说明 ref 和 delta loss 放大的是音频编辑信号，没有音频时找不到信号反而干扰 baseline。

7. **音频信息至关重要**。V_A_T 相比 V_T 在 R@1 上提升 56%~91%，SameSourceAny 提升 2%~5%。

8. **Target 击败同源视频能力良好**。最优配置（C1_120）在 87.6% 的情况下 target 排在所有同源负例前面。

9. **sound_event 远比 speech_topic 容易识别**（R@1 约 0.40 vs 0.28）。语音内容变化的识别需要更多探索。

### 11.2 后续建议

- **默认配置**：C1_ref_delta + 120 步 + lr=3e-4，配合 validation-based early stopping。
- **hn loss**：暂不加入默认配方，等更大数据规模验证。
- **speech_topic**：R@1 偏低，需专门的数据增强或 loss 设计。
- **扩大数据规模**：验证 120 步早停窗口是否随数据规模变化，协同效应是否持续。
